<span class="ds-eyebrow">Set up once</span>
<h2 id="setup">Three commands, then you forget about it</h2>
<p>Connect each machine to a private git repository, choose your files once from any machine, and go back to editing them as usual.</p>
</header>

<Terminal
	title="on each machine"
	code={`
$ dotsync init git@github.com:you/dotfiles.git      # clone, first sync, start the background agent
$ dotsync add ~/.gitconfig ~/.config/fish ~/.config/nvim   # once, from any machine
$ dotsync doctor                                    # check git access, the agent and every file
`}
/>
</section>

<section class="ds-section" aria-labelledby="rule">
<header>
<span class="ds-eyebrow">The model</span>
<h2 id="rule">One rule decides what happens to every file</h2>
<p>For each file, every machine remembers the version it last agreed on with the others. Comparing against that version shows who changed the file, so there's always exactly one right move.</p>
</header>

<section class="ds-section" aria-labelledby="why">
<header>
<span class="ds-eyebrow">Why dotsync</span>
<h2 id="why">Careful by design</h2>
<p>Most dotfile managers are deployment tools: you edit a source copy, then apply it everywhere. dotsync is a synchronizer: you edit the real file, and it takes care of the rest.</p>
</header>

<h2 id="fit">Is it the right tool for you?</h2>
</header>

<div class="ds-fit">
<div>
<h3>A good fit if you</h3>

- use two or more Macs or Linux machines
- want your configuration to simply *be the same* on all of them
- would rather never run a command to keep them in sync

</div>
<div>
<h3>Look elsewhere if you need</h3>

- **templates**, where one file renders differently per machine. [chezmoi](https://www.chezmoi.io/) is excellent at that; dotsync has [per-OS entries and per-machine exclusions](/dotsync/guides/differences/) instead
- **Windows** support
- **instant** sync. dotsync syncs every few minutes, by design

</div>
