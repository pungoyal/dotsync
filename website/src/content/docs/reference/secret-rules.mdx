A file is held back from uploading if its **path** or any line of its **content** matches a rule below, unless its entry sets `allow_secrets`. The rules are defined in [`internal/dotsync/secrets.go`](https://github.com/pungoyal/dotsync/blob/main/internal/dotsync/secrets.go).

## Path rules

Matching is case-insensitive. Patterns that contain `/` are matched against the path relative to `$HOME`, where `*` also matches `/`. The others are matched against the **file name only**.

| Pattern | Covers |
|---|---|
| `.ssh/id_*`, `.ssh/*_key` | SSH private keys |
| `*.pem`, `*.key`, `*.p12`, `*.pfx`, `*.jks`, `*.keystore` | TLS and signing keys, keystores |
| `*.kdbx`, `.password-store/*` | password databases |
| `.gnupg/private-keys-v1.d/*`, `.gnupg/secring.*`, `.gnupg/*.key` | GnuPG private keys (`gpg.conf` and `gpg-agent.conf` are fine) |
| `.local/share/keyrings/*` | desktop keyrings |
| `.config/mise/age.txt`, `.config/sops/age/*`, `Library/Application Support/sops/age/*` | age private keys used by mise and sops |
| `.aws/credentials`, `.aws/sso/*`, `.azure/*`, `.config/gcloud/*`, `.kube/config` | cloud credentials |
| `.docker/config.json`, `.netrc`, `.git-credentials`, `.pgpass`, `.vault-token`, `.config/gh/hosts.yml` | tool credentials |
| `.env`, `.env.*`, `*.env` | environment files |
| `*secret*`, `*credential*` | anything named like a secret |
| `.*history` | shell and REPL histories |

## Content rules

Each line is checked on its own:

| Detects | Pattern (simplified) |
|---|---|
| Private key blocks | `-----BEGIN … PRIVATE KEY-----` |
| age private keys | `AGE-SECRET-KEY-1…` + 58 characters |
| AWS access key IDs | `AKIA…` / `ASIA…` + 16 characters |
| GitHub tokens | `ghp_`, `gho_`, `ghu_`, `ghs_`, `ghr_` + 36 characters; `github_pat_…` |
| GitLab tokens | `glpat-…` |
| Slack tokens | `xoxb-`, `xoxp-`, … |
| API keys | `sk-…`, `sk-ant-…`, `sk-proj-…` (20+ characters) |
| Google API keys | `AIza…` + 35 characters |
| npm tokens | `_authToken=…` |
| Passwords in URLs | `scheme://user:password@…` |
| Assignments | `password`, `passwd`, `secret`, `token`, `api_key`, `access_key`, `client_secret` followed by `=` or `:` and a literal value of 8+ characters |

Assignments and URL passwords whose value starts with `$`, `$(`, a quote followed by `$`, or a brace, i.e. read from a variable or a command, are **not** flagged. For example, `password = $(pass show mail)` and `postgres://app:${PGPASSWORD}@db/app` are fine.

## Encrypted files

Encryption changes what is checked:

- **age files**, armored (`-----BEGIN AGE ENCRYPTED FILE-----`) or binary, are pure ciphertext. No rule applies, whatever the file is called.
- **sops files**, recognized by the encrypted `mac` sops writes into every format, skip the **path** rules, so `.env.json` or `secrets.yaml` can sync. Their encrypted values (`ENC[AES256_GCM,…]`) are skipped, but the content rules still apply to every other line, because sops leaves keys, comments and `_unencrypted` values readable.

## Exemptions

- A line containing `dotsync:allow-secret` is skipped.
- An entry with `"allow_secrets": true` (or added with `--allow-secrets`) skips every rule.

<Aside type="caution">
Pattern matching reduces risk; it can't guarantee anything. Keep the repository private, and if a secret does reach it, rotate the secret.
</Aside>

Found a credential format that should be caught, or a common false positive? [Open an issue](https://github.com/pungoyal/dotsync/issues/new/choose).
