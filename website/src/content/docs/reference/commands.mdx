```text
dotsync <command> [flags] [arguments]
```

- Flags can come before or after arguments. `-flag` and `--flag` both work, and `--` ends flag parsing.
- Every command accepts `-h` for its own help.
- `add`, `remove`, `set`, `describe`, `exclude`, `include` and `resolve` run a sync straight away, so you see the result immediately.

| Command | Alias | Purpose |
|---|---|---|
| [`init`](#init) | | set up this machine |
| [`doctor`](#doctor) | | check the setup and explain how to fix problems |
| [`update`](#update) | | install the latest release, verified |
| [`add`](#add) | | start managing files or directories, on every machine |
| [`remove`](#remove) | `rm` | stop managing entries, on every machine |
| [`set`](#set) | | change an entry's ignore patterns, OS, permissions, write strategy or description |
| [`describe`](#describe) | | change an entry's description |

## init

```text
dotsync init [flags] <git-url>
```

Sets up this machine. It clones the repository, creates the manifest if the repository is empty, writes the [machine configuration](/dotsync/reference/configuration/), copies the binary to `~/.local/bin`, runs the first sync, and installs the [background agent](/dotsync/guides/background-agent/). Safe to run again.

| Flag | Description |
|---|---|
| `--keep-existing` | report existing, differing local files as conflicts instead of backing them up and replacing them |
| `--branch <name>` | branch to sync (default `main`) |
| `--interval <seconds>` | background sync interval (default `300`) |
| `--no-agent` | don't install the background agent |
| `--no-install` | don't copy the binary to `~/.local/bin` |

## doctor

```text
dotsync doctor
```

Checks everything dotsync depends on:

- the git version
- the configuration and cache clone
- that the remote is reachable **without prompts**, exactly as the background agent will reach it
- the agent, and whether `dotsync` is on your `PATH`
- how long ago the last sync ran
- conflicts, blocked files and errors
- backup usage

Each problem comes with a `→` line saying how to fix it.

```console frame="terminal"
$ dotsync doctor
dotsync doctor
  ✓ dotsync 0.2.0 (…) go1.27.1 darwin/arm64
  ✓ git version 2.54.0
  ✓ configuration: ~/.config/dotsync/config.json
  ✗ remote rejects authentication
      git@github.com: Permission denied (publickey).
      → make `git ls-remote git@github.com:you/dotfiles.git` work without a prompt: …
  ✓ background agent: launchd agent loaded
  ✓ 12 managed entries, 148 files
  · backups: 6 file(s), 41.2 KiB in ~/.local/state/dotsync/backups (older than 90 days are pruned)
```

Exits `1` if any check fails (`✗`); warnings (`!`) don't change the exit status.

## update

```text
dotsync update [--check] [--version vX.Y.Z] [--require-attestation]
```

Replaces the running binary with the latest release, applying the same checks as the install script. It verifies the **SHA-256 checksum**, plus the **signed build provenance** when the GitHub CLI is available, before replacing anything. The binary is swapped atomically. If the background agent runs a different copy (`~/.local/bin/dotsync`), that copy is updated too, so the next scheduled sync already uses the new version.

| Flag | Description |
|---|---|
| `--check` | only report whether a newer release exists |
| `--version vX.Y.Z` | install a specific release instead of the latest, including an older one |
| `--require-attestation` | refuse to update unless the build provenance verifies |

`dotsync doctor` also mentions when an update is available. Development builds (`make build`) only update with an explicit `--version`.

## add

```text
dotsync add [flags] <path>...
```

Starts managing files or directories on every machine. Paths must be inside `$HOME`. Files that look like secrets are refused. For directories, `add` reports how many files will be held back as secrets.

| Flag | Description |
|---|---|
| `-d`, `--description <text>` | description (single path only; defaults to the file name) |
| `--source <path>` | location under `files/` in the repository (single path only). The default is derived from the path: `~/.config/fish/config.fish` becomes `fish/config.fish` |
| `--ignore <glob>` | directories: a pattern not to sync. Repeatable |
| `--os darwin\|linux` | only manage the entry on this OS. Repeatable |
| `--allow-secrets` | turn off the [secret filters](/dotsync/reference/secret-rules/) for this entry |
| `--no-sync` | only queue the change; the next sync sends it |

## remove

```text
dotsync remove [--no-sync] <path|source>...
```

Stops managing entries on **every** machine. Local copies stay in place everywhere as ordinary unmanaged files. The content remains in the repository history.

## set

```text
dotsync set <path|source> [changes]
```

Changes an entry in the shared manifest, for every machine.

| Flag | Change |
|---|---|
| `-d`, `--description <text>` | set the description |
| `--ignore <glob>` | add an ignore pattern (directories). Repeatable |
| `--unignore <glob>` | remove an ignore pattern. Repeatable |
| `--clear-ignore` | remove every ignore pattern |
| `--os darwin\|linux` | only manage the entry on these operating systems (replaces the current list). Repeatable |
| `--any-os` | remove the OS restriction |
| `--mode <octal>` | force permissions on every machine, e.g. `0600` |
| `--no-mode` | stop forcing permissions |
| `--write atomic\|inplace` | how local files are replaced |
| `--allow-secrets`, `--allow-secrets=false` | turn the [secret filters](/dotsync/reference/secret-rules/) off or back on for this entry |
| `--no-sync` | only queue the change |

The result is validated before anything is queued, so an invalid mode or OS is refused immediately. Ignore changes are recorded as *additions and removals*, so edits made on two machines at once combine rather than overwrite each other. To change an entry's `source` or `target`, `remove` it and `add` it again.

## describe

```text
dotsync describe <path|source> <description>
```

Shortcut for `dotsync set <path|source> --description <description>`.

## exclude and include

```text
dotsync exclude [--no-sync] <path|source>...
dotsync include [--no-sync] <path|source>...
dotsync exclude            # list what's excluded on this machine
```

`exclude` stops managing entries **on this machine only**. The entries stay in the shared manifest, and the local files are left exactly as they are. `include` manages an excluded entry again. On that first sync, a local file that differs from the shared version is handled as on a new machine: backed up and replaced, or a conflict with `on_existing: "conflict"`. Both commands edit `exclude` in the [machine configuration](/dotsync/reference/configuration/).

## sync

```text
dotsync sync [-q]
```

Runs one synchronization. The background agent runs `dotsync sync -q` on a schedule.

| Flag | Description |
|---|---|
| `-q`, `--quiet` | print nothing; exit immediately (status 0) if another sync is running; post desktop notifications for new conflicts and authentication failures |

The output is explained in [Output and exit codes](/dotsync/reference/output/).

## status

```text
dotsync status [-v] [--fetch] [--json]
```

Shows every entry and its state on this machine, plus the last sync result, the agent state, queued changes and conflicts.

| Flag | Description |
|---|---|
| `-v` | list every file, not just those that need attention |
| `--fetch` | fetch from the remote first. Without it, `status` compares against the last fetched state, which also works offline |
| `--json` | machine-readable output |

## list

```text
dotsync list [--json]
```

Prints the shared manifest, including entries that are skipped on this machine.

## diff

```text
dotsync diff [--fetch] [path...]
```

Shows a unified diff from the remote version (`-`) to the local version (`+`) for every file that differs, or only for the given paths. A directory path covers everything below it.

## resolve

```text
dotsync resolve <path>... --keep local|remote
```

Settles [conflicts](/dotsync/guides/resolve-conflicts/). `--keep local` sends this machine's version. `--keep remote` backs up the local file and installs the remote version. A directory path resolves every conflict below it.

## log

```text
dotsync log [-n <count>]
```

Shows recent commits to the shared repository (default 20). Each commit names the machine that made it.

## agent

```text
dotsync agent install|uninstall|status
```

Manages the [background agent](/dotsync/guides/background-agent/). Run `install` again after changing `interval`, moving `git`, or changing `XDG_*` variables.

## version

```text
dotsync version
```

Prints the version, commit, build date, Go version and platform.
