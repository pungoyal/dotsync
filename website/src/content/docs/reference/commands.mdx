```text
dotsync <command> [flags] [arguments]
```

- Flags can come before, between or after arguments. `-flag` and `--flag` are the same, and a value can follow a space or an `=`: `--interval 600` or `--interval=600`. `--` ends flag parsing.
- `dotsync help <command>`, or `-h` after any command, prints its usage and flags.
- Every command that changes something (`add`, `remove`, `set`, `describe`, `exclude`, `include`, `resolve` and `import stow --apply`) runs a sync straight away, so you see the result immediately.
- A command that needs the lock waits up to a minute for a running sync to finish.

## init

<CommandSynopsis name="init" />

Sets up this machine. It clones the repository into `~/.local/share/dotsync/repo` and, if the repository is empty, creates the manifest there and pushes it. Then it writes the [machine configuration](/dotsync/reference/configuration/), copies the running binary to `~/.local/bin/dotsync` (unless Homebrew or apt installed it), runs the first sync, and installs the [background agent](/dotsync/guides/background-agent/).

`init` is safe to run again, for example to re-install the agent or to change the branch or interval. Flags you don't pass keep their saved values. A machine can only sync with one repository; to [switch](/dotsync/project/faq/#how-do-i-move-to-a-different-remote), change the remote first.

<CommandFlags name="init" />

With `--keep-existing`, existing local files that differ from the shared version become [conflicts](/dotsync/guides/resolve-conflicts/) instead of being backed up and replaced. It's saved as [`on_existing`](/dotsync/reference/configuration/), so it also applies to entries added later. See [Add another machine](/dotsync/guides/add-a-machine/#files-the-machine-already-has).

## doctor

<CommandSynopsis name="doctor" />

Checks everything dotsync depends on, in order, and says how to fix what's wrong:

- this version, and whether a newer release exists
- that `git` is installed, and version 2.20 or newer
- the configuration, and that the cache clone exists and points at the configured remote
- that the remote is reachable **without prompts**, exactly as the background agent will reach it, and has the configured branch
- that the agent is installed and loaded, that the binary it runs exists, and that its definition is current
- that `dotsync` is on your `PATH`
- when the last sync ran, and whether it reached the remote
- conflicts, blocked files, errors and queued changes, judged against the last fetched state
- how many backups there are, and how much space they use

<Terminal code={doctorOut} />

Each line starts with `✓` (fine), `·` (information), `!` (a warning) or `✗` (a failure), and problems come with a `→` line saying what to do. `doctor` exits with status `1` if any check failed; warnings don't change the exit status. It never changes your files, the repository or the agent.

## update

<CommandSynopsis name="update" />

Replaces this binary with the latest release, after the same checks as the install script: the **SHA-256 checksum** always, and the **signed build provenance** when the GitHub CLI is installed. If the background agent runs a different copy (`~/.local/bin/dotsync`), that copy is replaced too, and the agent is then re-installed so its next run uses the new version with matching settings.

<CommandFlags name="update" />

<Terminal code={updateOut} />

If Homebrew or apt installed dotsync, `update` changes nothing and prints the package manager's command instead (`brew upgrade dotsync`, or `sudo apt install --only-upgrade dotsync`); `--check` works as usual.

Binaries are replaced atomically, and nothing is replaced if a check fails. A development build, one without a release version, is only replaced when you pass `--version`. `update` looks up the latest release through the GitHub API; set `GITHUB_TOKEN` if you hit its rate limit.

## import

<CommandSynopsis name="import" />

Moves this machine from [GNU Stow](https://www.gnu.org/software/stow/) to dotsync. It finds the symlinks in `$HOME` that point into the stow directory and shows what it would do. With `--apply` it replaces each link with a real copy of its content and starts managing it. The stow directory is only read, never changed. Name packages after the directory to import only those. Requires `dotsync init`.

<CommandFlags name="import" />

<Terminal code={importOut} />

- A folded directory link becomes one directory entry. A directory Stow unfolded becomes one entry when everything in it belongs to a single package; otherwise its links are imported file by file. `$HOME`, `~/.local`, `~/.ssh`, `~/.gnupg` and the XDG base directories never become an entry, and neither does a directory that contains a file that looks like a secret: its files are imported one by one so the secret can be skipped. If Stow folded `~/.ssh` or `~/.gnupg` into a single link, that link is skipped.
- Paths that are already managed (for example on a second machine) are only turned into real files; the manifest is not changed.
- Files that look like [secrets](/dotsync/reference/secret-rules/) are skipped and keep their link. With `--apply`, the run ends by listing the paths that still link into the stow directory instead of saying it can be removed. `--allow-secrets` imports them too, and marks only those entries `allow_secrets`.
- `dot-` names from `stow --dotfiles` are understood.
- If a source file cannot be read, that entry is reported as FAILED and none of its links is touched; the other entries are still imported and the exit code is 1. If a replacement still fails partway through a directory, the command names the files it already turned into real files and the `dotsync add <directory>` that brings the whole entry under management.

See [Migrate from another tool](/dotsync/guides/migrate/).

## add

<CommandSynopsis name="add" />

Starts managing files or directories, **on every machine**. Paths must be inside your home directory. A file that looks like a secret is refused; for a directory, `add` tells you how many files will be held back instead. See [Manage files and directories](/dotsync/guides/manage-files/) for how sources are chosen and what can't be added.

<CommandFlags name="add" />

`-d` and `--source` can only be used with a single path.

## remove

<CommandSynopsis name="remove" />

Stops managing entries **on every machine**. The local copies stay where they are, everywhere, as ordinary files. The content stays in the repository's history. Name an entry by its path on this machine or by its source.

<CommandFlags name="remove" />

## set

<CommandSynopsis name="set" />

Changes one entry in the shared manifest, **for every machine**. Name the entry by its path on this machine or by its source.

<CommandFlags name="set" />

- `--os` replaces the whole list; `--any-os` removes it. They can't be combined, and neither can `--mode` with `--no-mode`, or `--clear-ignore` with `--unignore`.
- Ignore changes are recorded as additions and removals, so changes made on two machines at once combine.
- The result is checked before anything is queued, so an invalid mode, OS or write strategy is refused straight away.
- Boolean flags take `=false` to turn something off: `--allow-secrets=false` turns the [secret rules](/dotsync/reference/secret-rules/) back on.
- To change an entry's source or target, `remove` it and `add` it again.

## describe

<CommandSynopsis name="describe" />

A shortcut for `dotsync set <path|source> --description <description>`.

## exclude

<CommandSynopsis name="exclude" />

Stops managing entries **on this machine only**. The entries stay in the shared manifest, and the local files are left exactly as they are. With no arguments, lists what's excluded here. Exclusions are saved as `exclude` in the [machine configuration](/dotsync/reference/configuration/).

<CommandFlags name="exclude" />

## include

<CommandSynopsis name="include" />

Manages an excluded entry on this machine again. On its first sync, a local file that differs from the shared version is handled as on a new machine: backed up and replaced, or reported as a conflict if the machine uses `--keep-existing`.

<CommandFlags name="include" />

## status

<CommandSynopsis name="status" />

Shows every entry and its state on this machine, with the last sync's result, the agent's state, changes queued but not yet pushed, and conflicts. Directory entries also list the files that need attention. [Output and exit codes](/dotsync/reference/output/#status) explains every state.

<CommandFlags name="status" />

Without `--fetch`, `status` compares against the last fetched state, which is at most one sync interval old and works offline. It always exits with status `0` once it has run.

## list

<CommandSynopsis name="list" />

Prints the shared manifest, sorted by source, including entries this machine skips. Entries limited to some operating systems show them in brackets.

<Terminal code={listOut} />

<CommandFlags name="list" />

## sync

<CommandSynopsis name="sync" />

Runs one synchronization now, rather than waiting for the agent. [How sync works](/dotsync/concepts/how-sync-works/#one-sync-step-by-step) describes what it does, and [Output and exit codes](/dotsync/reference/output/) its output.

<CommandFlags name="sync" />

The background agent runs `dotsync sync -q`. Besides silencing output, `-q` makes `sync` exit straight away, with status `0`, if another sync is running, and lets it post [desktop notifications](/dotsync/guides/background-agent/#logs-and-notifications) for new conflicts and git problems.

## diff

<CommandSynopsis name="diff" />

Shows a unified diff from the repository's version (`-`) to this machine's (`+`) for every managed file that differs, or only for the given paths. A directory path covers everything below it. Binary files are reported as differing, without a diff.

<CommandFlags name="diff" />

## resolve

<CommandSynopsis name="resolve" />

Settles [conflicts](/dotsync/guides/resolve-conflicts/). It fetches first, then syncs straight away. `--keep local` sends this machine's version; `--keep remote` backs up the local file and installs the repository's. A directory path resolves every conflict below it. It fails if there's no conflict at the paths you give.

<CommandFlags name="resolve" />

## log

<CommandSynopsis name="log" />

Shows recent commits to the shared repository as of the last fetch: short hash, date and time, and message. Every message starts with the name of the machine that made it.

<CommandFlags name="log" />

## agent

<CommandSynopsis name="agent" />

Manages the [background agent](/dotsync/guides/background-agent/).

| Action | What it does |
|---|---|
| `install` | writes the launchd agent, systemd units or crontab line and loads it, replacing any previous definition. Run it after changing `interval`, moving `git`, or changing `XDG_*` variables |
| `uninstall` | unloads and removes it |
| `status` | says whether it's installed and loaded |

## version

```text
dotsync version
dotsync --version
```

Prints the version, the commit it was built from and that commit's date, the Go version, and the platform.

## help

```text
dotsync help
dotsync help <command>
```

Lists every command, or shows one command's usage and flags. `dotsync`, `dotsync -h` and `dotsync --help` also list every command.
