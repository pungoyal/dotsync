description: How dotsync stops credentials from reaching your repository, and how to structure dotfiles so secrets stay local.

dotsync's rule is simple: **secrets never leave the machine**. They aren't encrypted into the repository; they're kept out of it. The exact patterns are listed in the [secret detection rules](/dotsync/reference/secret-rules/).

## What you'll see

**When adding** a file that looks like it holds a credential, `add` refuses it:

```console frame="terminal"
$ dotsync add ~/.aws/credentials
dotsync: ~/.aws/credentials: refusing to manage it: path looks like a secret (matches '.aws/credentials') (use -allow-secrets if the remote is meant to hold it)
```

**When a managed file later gains a secret**, for example after you paste a token into your shell config, that file is **BLOCKED**. Its new version isn't sent, and `sync` and `status` tell you why. The previous version in the repository is unaffected. Remove the secret and syncing resumes.

```console frame="terminal"
$ dotsync sync
  BLOCKED   ~/.config/fish/config.fish  (content looks like a GitHub token)
dotsync: 1 blocked
```

**Inside managed directories**, credential files such as `~/.config/gh/hosts.yml` are simply not uploaded. `add` tells you how many were held back.

## Move secrets out of synced files

The clean fix is to keep the secret in a separate, **unmanaged** file, and have the synced file load it:

<Tabs syncKey="shell">
<TabItem label="fish">
```fish title="~/.config/fish/config.fish (synced)"
test -f ~/.config/fish/secrets.fish; and source ~/.config/fish/secrets.fish
```
```fish title="~/.config/fish/secrets.fish (local only, never added)"
set -gx GITHUB_TOKEN ghp_…
```
</TabItem>
<TabItem label="zsh / bash">
```sh title="~/.zshrc (synced)"
[ -f ~/.secrets.sh ] && . ~/.secrets.sh
```
```sh title="~/.secrets.sh (local only, never added)"
export GITHUB_TOKEN=ghp_…
```
</TabItem>
<TabItem label="git">
```ini title="~/.gitconfig (synced)"
[include]
	path = ~/.gitconfig.local
```
```ini title="~/.gitconfig.local (local only, never added)"
[github]
	token = ghp_…
```
</TabItem>
</Tabs>

Better still, read secrets from a password manager or the OS keychain when needed: `op read`, `pass`, `security find-generic-password` (macOS), `secret-tool` (Linux).

## Encrypted files

Files encrypted with [age](https://age-encryption.org) or [sops](https://getsops.io) sync without any exception, even when their name looks like a secret, such as `.env.json` or `secrets.yaml`. Only ciphertext reaches the repository. The age **private key** that decrypts them is always refused, so copy it to each new machine yourself. `dotsync doctor` warns on a machine that has encrypted files but no key. See [encrypted files](/dotsync/reference/secret-rules/#encrypted-files) for exactly what is checked.

## False positives

Sometimes a line only *looks* like a secret. You have two options:

- **One line:** add `dotsync:allow-secret` anywhere on it, usually in a comment:

  ```ini
  password_file = ~/.config/mail/app-password   # dotsync:allow-secret
  ```

- **A whole entry:** add it with `dotsync add --allow-secrets`, or set `"allow_secrets": true` in the manifest.

<Aside type="danger">
Only opt out when the repository really is an acceptable place for that content. If a real secret ever reaches the repository, **rotate it**. Deleting it from the latest commit doesn't remove it from the history.
</Aside>
