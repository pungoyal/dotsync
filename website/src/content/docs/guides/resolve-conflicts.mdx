A **conflict** means the same file changed on this machine **and** on another machine since they last agreed. dotsync never guesses which version you want. It changes nothing on this machine and nothing in the repository, and it waits for you. All your other files keep syncing normally in the meantime.

## When they happen

- You edited a file on your laptop while it was offline, and edited it on your desktop too.
- Two machines edited the same file within the same sync interval.
- The same new file appeared inside a managed directory on two machines.
- A file became managed on a machine that already had a different version, and that machine uses `--keep-existing`.

Deleting a file on one machine while it changed on another is **not** a conflict. The changed version wins, so no work is lost.

## How you find out

- `dotsync sync` prints a `CONFLICT` line.
- `dotsync status` lists the file under *conflicts*.
- The background agent posts a **desktop notification** the first time it sees a conflict.

## Settle a conflict

<Steps>

1. **See what differs.** The remote version is on the `-` side and yours is on the `+` side:

   ```console frame="terminal"
   $ dotsync diff ~/.gitconfig
   === ~/.gitconfig  [conflict]
   --- remote/gitconfig
   +++ local/gitconfig
   @@ -1,3 +1,3 @@
    [user]
   -	email = me@work.example
   +	email = me@home.example
   ```

2. **Choose.** Pick one:

   | You want | Run |
   |---|---|
   | this machine's version everywhere | `dotsync resolve ~/.gitconfig --keep local` |
   | the other version here | `dotsync resolve ~/.gitconfig --keep remote` |
   | a mix of both | edit the local file until it's right, then `dotsync resolve ~/.gitconfig --keep local` |

   With `--keep remote`, your version is **backed up** first.

3. **Done.** `resolve` syncs straight away. Other machines pick up the result on their next sync.

</Steps>

<Aside type="tip">
If you edit the file so it matches the remote version exactly, the conflict clears by itself on the next sync. You don't need `resolve`.
</Aside>

You can resolve every conflict under a directory at once:

```sh
dotsync resolve ~/.config/nvim --keep local
```

## Why resolving is safe

`resolve` doesn't copy anything itself. It only records which version counts as "last agreed", and the normal sync rules then do the work with all their safety checks. If a third machine changed the file again in the meantime, you get a fresh conflict instead of a lost edit. The details are in [How sync works](/dotsync/concepts/how-sync-works/).
