`dotsync init` installs a scheduled job that runs `dotsync sync -q` every five minutes. There's no long-running daemon: the job starts, syncs, and exits.

| Platform | Mechanism | Defined in |
|---|---|---|
| macOS | launchd user agent `io.github.dotsync` | `~/Library/LaunchAgents/io.github.dotsync.plist` |
| Linux with systemd | user timer `dotsync.timer` | `~/.config/systemd/user/dotsync.{service,timer}` |
| Linux without systemd | crontab line tagged `# dotsync-agent` | your user crontab |

It also runs at login (macOS) or one minute after boot (systemd). The systemd timer catches up on runs missed while the machine was asleep.

```sh
dotsync agent status       # installed? loaded?
dotsync agent install      # (re)install, e.g. after changing the interval
dotsync agent uninstall
```

## Resource use

The agent is built to be invisible on a laptop battery and predictable in what it does.

**When nothing changed**, which is almost every run, a sync:

- takes about 60–70 ms, and runs 2 `git` processes (`fetch` and `rev-parse`)
- **writes nothing to disk**: no log line, no state rewrite (only the state file's timestamp is touched), no git index, reflog or `FETCH_HEAD` writes
- re-reads **no file contents**: files whose size, modification time, change time, inode and mode are unchanged are recognised from a cache. As in git, files modified in the last two seconds are always re-read.

**Priority:** it runs at background priority. On macOS that means launchd `ProcessType Background`, low-priority I/O and `Nice 10`. On Linux it means the `idle` CPU and I/O scheduling classes. It uses a single OS thread with a 64 MiB soft memory limit, and its peak memory is about 16 MiB for the fraction of a second it runs.

**No randomness:**

- Syncs run on a fixed interval.
- The systemd timer has `RandomizedDelaySec=0`, with a fixed 1-minute accuracy window so systemd can batch the wake-up with others.
- launchd never wakes a sleeping Mac for it. A run missed during sleep happens once on wake.
- Housekeeping runs on a fixed calendar instead of whenever git decides:
  - backups are pruned at most once a day
  - the cache clone gets a full reset at least once a day, and `git gc` once a week
  - git's own automatic gc and maintenance are turned off
- Push retries after another machine pushes first happen immediately, with no random back-off.

## Change the interval

Set `interval` (in seconds) in `~/.config/dotsync/config.json`, then run `dotsync agent install`. With cron the interval is rounded to whole minutes.

## Environment

launchd and cron don't read your shell configuration. So when the agent is installed, dotsync writes `PATH` (including the directory `git` was found in), `HOME` and any `XDG_*` base directories you've set into the job definition. If you move `git` or change those variables, run `dotsync agent install` again.

## Git access without prompts

The agent can't type passwords or passphrases. `git ls-remote <your-url>` must succeed without any prompt:

<Tabs>
<TabItem label="SSH on macOS">
Store the key's passphrase in the Keychain once, and let `ssh` load it automatically:

```ssh-config title="~/.ssh/config"
Host github.com
  AddKeysToAgent yes
  UseKeychain yes
  IdentityFile ~/.ssh/id_ed25519
```
```sh
ssh-add --apple-use-keychain ~/.ssh/id_ed25519
```
</TabItem>
<TabItem label="SSH on Linux">
systemd user services usually can't reach your desktop session's `ssh-agent`. The simplest reliable option is a **dedicated deploy key without a passphrase**, allowed to write to this one repository:

```sh
ssh-keygen -t ed25519 -N '' -f ~/.ssh/dotsync -C "dotsync@$(hostname)"
```
```ssh-config title="~/.ssh/config"
Host github.com
  IdentityFile ~/.ssh/dotsync
  IdentitiesOnly yes
```
Add `~/.ssh/dotsync.pub` as a deploy key with **write access** in the repository's settings.
</TabItem>
<TabItem label="HTTPS">
Use a credential helper, and authenticate once interactively:

```sh
git config --global credential.helper osxkeychain   # macOS
git config --global credential.helper libsecret     # Linux desktop
gh auth setup-git                                    # or let the GitHub CLI handle it
```
</TabItem>
</Tabs>

Check it with `dotsync doctor`, which reaches the remote exactly as the agent does. If authentication fails, `doctor` and `dotsync status` show the exact git error, and the agent posts a desktop notification.

## Logs and notifications

| File | Contents |
|---|---|
| `~/.local/state/dotsync/sync.log` | every change, conflict and error, plus one summary line per sync (rotated at 1 MiB) |
| `~/.local/state/dotsync/agent.log` | anything the scheduled job printed |

The agent notifies you when a **new** conflict appears or git starts failing to authenticate. Set `DOTSYNC_NO_NOTIFY=1` to turn this off.

- **Linux:** notifications go through `notify-send` and show the dotsync icon.
- **macOS:** notifications appear in Notification Center. To show the dotsync icon instead of the Script Editor icon, install [terminal-notifier](https://github.com/julienXX/terminal-notifier) (`brew install terminal-notifier`), and dotsync uses it automatically.

<Aside type="tip" title="Headless Linux servers">
Without lingering, systemd user timers only run while you're logged in. Enable it once with `loginctl enable-linger $USER`.
</Aside>
